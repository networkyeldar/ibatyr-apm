# Подробный анализ, общий отчёт и PDF

## Работа в интерфейсе

1. Выберите сервис, период и при необходимости экземпляр на странице JVM.
2. Выберите внешний или локальный профиль в блоке «Общий анализ графиков».
3. Нажмите «Анализировать все графики». Анализ запускается сразу, без дополнительного окна подтверждения. Настроенный профиль и действующая AI-лицензия обязательны.
4. Результат содержит резюме, влияние, выводы с E-идентификаторами доказательств, гипотезы, приоритетные проверки и ограничения. Разверните доказательство, чтобы сверить числа.
5. Нажмите «Скачать PDF». Он содержит тот же результат, метаданные выбранного периода, графики и реестр доказательств. Это снимок анализа: последующие Live-обновления его не меняют.

Для трассировки: выберите вызов, при необходимости измените вопрос и нажмите
«Анализировать трассировку». Никакого дополнительного preview не требуется.
Один клик запускает подготовку контекста и один запрос к LLM; ожидание ответа
зависит от OAP и модели. Live никогда не отправляет запросы к LLM автоматически.
Кнопки блокируются на время анализа. Лимит выходных токенов остаётся заданным
в профиле; для подробного отчёта рекомендуемый диапазон 4096–8192. Если ответ
обрезан, UI сообщает об этом и не показывает неполный JSON как готовый результат.

## Формат ответа и диагностика LLM

В настройках профиля добавлен «Формат ответа ИИ»:

- **Автоматически** (также для существующих настроек): для официального
  `https://api.openai.com/v1` и моделей `gpt-4o-mini`, `gpt-4o-mini-2024-07-18`,
  `gpt-4o`, `gpt-4o-2024-08-06`, `gpt-4o-2024-11-20` отправляется
  `response_format: json_schema` с `strict: true`. Схема содержит только
  E-идентификаторы текущего контекста и фиксированные поля отчёта.
- **Строгая схема JSON**: включить явно, если выбранная модель/шлюз поддерживает
  этот параметр Chat Completions. Поддержка зависит от версии сервера модели.
- **JSON mode**: API гарантирует JSON, но форма полей и ссылки всё ещё могут
  оказаться неверными; оболочка проверяет их после получения ответа.
- **По инструкции**: совместимость с API без `response_format`. Этот режим
  также используется автоматически для остальных моделей/шлюзов/локальных API.

Модель, ключ и лимит токенов при обновлении не меняются. Для GPT-4o mini на
официальном API достаточно установленного по умолчанию режима «Автоматически».
Документация: [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).

Если отчёт не сформирован, сообщение теперь различает:

- `json_syntax`: модель вернула некорректный JSON;
- путь поля, например `next_checks[0]`: неверный тип или превышение лимита;
- `unknown_evidence`: ссылка отсутствует в отправленных измерениях;
- `length`: ответ обрезан — увеличьте максимум выходных токенов вручную;
- `refusal/content_filter`: отказ модели;
- пустой `message.content`: нет итогового текста.

Сырые ответы/ключи не включаются в диагностику. Неверные ссылки не исправляются
догадками, непроверенный ответ не превращается в PDF. Повторные платные запросы
и переключение режима после ошибки не выполняются автоматически.
Кнопка «Проверить сохранённый профиль» проверяет доступ к модели коротким
запросом; успешная проверка не означает, что модель уже сформировала отчёт.

## Область и данные

- Общий анализ: метрики одного сервиса + одной выбранной JVM. Если выбор JVM ещё не сделан, берётся первый экземпляр за период; его имя указано в отчёте. Все экземпляры не объединяются.
- Если JVM отсутствует, её графики/доказательства будут пустыми, а ограничения — явными. Анализ доступных метрик сервиса возможен.
- В модель передаются агрегаты, покрытие, экстремумы и совпадающие минуты, а не все 1440 точек каждого графика. PDF строится из сохранённых минутных точек.
- Алерты — первая страница до 50 событий по всем сервисам. В контекст входят только числа по уровням и число событий выбранного сервиса. Это не полный перечень инцидентов; тексты алертов не отправляются.
- Трассировка: тайминги, относительный порядок операций, до 40 выбранных spans и 8 групп SQL. Группировка использует максимум 2000 возвращённых spans. Сумма вложенных длительностей не равна времени запроса.
- Имена сервисов обезличены в контексте модели; IP, параметры SQL и сырые stack traces не передаются. Имена таблиц и колонок остаются в SQL-шаблонах. Пользовательский вопрос передаётся как введён.
- Ответы модели проходят проверку JSON и существования evidence_ids. Это не проверка правильности причинного вывода. Запросы SQL и команды не выполняются.

## Графики

«По доступным данным» убирает пустое начало и конец графика, сохраняя внутренние
пропуски. Покрытие и фактически показанные границы видны над графиком. Это меняет
только масштаб; фильтр, выборка и область ИИ-анализа остаются прежними.
«Весь период» показывает полный интервал с затенёнными пропусками.
Дата добавляется к делениям оси, когда период пересекает полночь.

«24 часа до сейчас» — скользящий период, например 12:50 вчера → 12:50 сегодня.
«Календарный день · 00–24» — от полуночи выбранной даты до следующей полуночи
в выбранном часовом поясе. На текущем дне будущие часы не заполняются данными.

Live — опрос каждые 15/30/60 секунд. Пульсирует только свежая последняя точка
(не старше пяти минут); при ошибке обновления, историческом просмотре или скрытой
вкладке пульсация отключается. Значения не генерируются ради анимации.
Поддерживается системная настройка уменьшения движения.

## API

Все маршруты требуют сессию. POST дополнительно требует X-CSRF-Token.

- `POST /api/ai/llm/trace-analysis`: trace_id, provider, request_id, question.
- `POST /api/ai/llm/overview-analysis`: service_id, start, end, optional instance_id, provider, request_id, question.
- `GET /api/ai/reports/{report_id}.pdf`: скачать сформированный отчёт владельца текущей сессии.

request_id должен быть уникальным для нового нажатия. Повтор завершённого
запроса с теми же параметрами возвращает сохранённый результат без нового
расхода токенов; другой payload с тем же ID отклоняется. Один активный анализ
на сессию и два на процесс. Автоматических платных повторов нет.

PDF/результаты хранятся в памяти до часа, максимум 20 отчётов на процесс.
При достижении лимита старейший PDF удаляется раньше. Перезапуск очищает их;
скачайте важные отчёты. Один worker Uvicorn. Отчёт из другой сессии недоступен.
PDF создаётся локально с кириллическими шрифтами; дополнительные CDN или
внешние сервисы конвертации не используются.

## Установка обновления на существующий сервер

Из проверенного checkout репозитория:

```bash
sudo python3 tools/update_workspace.py \
  --app-dir /opt/ibatyr/shell/0.5.0-rc1 \
  --port 8011
```

Установщик проверяет WorkingDirectory службы, готовность OAP/оболочки,
компилирует новые модули, устанавливает ReportLab 4.4.9 в существующий venv и
проверяет загрузку PDF-модуля/шрифтов. Затем создаёт резервную копию файлов,
кратко останавливает только `ibatyr-apm.service`, обновляет код/UI/шрифты,
запускает и проверяет готовность и версию HTML. При ошибке возвращает старые
файлы и запускает прежнюю оболочку. Добавленные Python-зависимости при откате
не удаляются. Пользовательские изменения UI сохраняются в резервной копии,
но заменяются новым UI. Настройки, ключи API, лицензия и данные Elasticsearch
не переносятся в исходники и не заменяются. OAP/Elasticsearch не перезапускаются.

`tools/update_jvm.py` остаётся совместимым входом в тот же полный updater.
Для новой установки обычный shell installer устанавливает зависимости из
`shell/requirements.txt`; PDF-шрифты уже входят в пакет.
