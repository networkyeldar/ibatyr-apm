# Пользователи iBatyr APM

Войдите прежним логином и паролем. При первом запуске обновления существующий
аккаунт автоматически переносится в базу пользователей с ролью администратора.
Откройте «Пользователи» в меню слева или одноимённую кнопку вверху.

## Возможности

- Создание пользователя: уникальный логин, пароль от 12 до 1024 символов, роль.
- Логин: латинские буквы, цифры, точка, дефис, `_` и `@`; первый символ — буква
  или цифра. Регистр новых логинов не различается. Максимум 200 аккаунтов.
- Администратор: просмотр APM, запуск AI, управление аккаунтами, подключениями
  AI и лицензией.
- Пользователь APM: просмотр всех сервисов, JVM, алертов, трассировок и SQL этой
  установки; запуск AI с настроенным профилем при действующей AI-лицензии,
  экспорт данных и собственного PDF. Изменение настроек и аккаунтов запрещено
  на сервере, даже при прямом API-запросе.
- В списке выберите «Изменить»: изменить роль, заблокировать/разблокировать
  аккаунт или назначить новый пароль. Постоянного удаления аккаунтов нет.
- Смена пароля/роли/состояния отзывает все прежние сессии пользователя.
  Собственный пароль администратор также может изменить здесь: потребуется
  повторный вход. Собственную роль и блокировку менять нельзя.
- Журнал хранит до 1000 последних административных действий; UI показывает
  последние 100. Пароли и хеши в журнал не записываются. Это локальный журнал,
  не защищённое от администратора ОС внешнее хранилище аудита.

Пароль задаёт администратор. Автоматической отправки приглашений, восстановления
по email, принудительной смены временного пароля, MFA и SSO в этой версии нет.
Передавайте назначенный пароль сотруднику по принятому защищённому каналу.

## Границы доступа

Это учётные записи **нашей оболочки `/ai/` и API `/api/ai/`**. Они не добавляют
авторизацию к исходному UI SkyWalking (`/marketplace`, `/graphql` и другим его
маршрутам) или непосредственно к OAP/Elasticsearch. При использовании единого
Nginx на 8080 права оболочки не распространяются на соседние маршруты upstream.
Доступ к ним ограничивается отдельно сетевыми правилами или авторизацией прокси.

Разграничения по сервисам/клиентам нет: все пользователи видят одну установку.
Пользователь может расходовать токены настроенного AI-профиля. Действующие
ограничения параллелизма сохраняются. Для доступа вне доверенной сети нужен HTTPS.

## Хранение и обновления

`users.sqlite3` создаётся рядом с конфигурацией, заданной `SW_AI_CONFIG`.
Для стандартной установки: `/var/lib/ibatyr-apm/users.sqlite3`. Права файла 0600;
пароли хранятся как PBKDF2-HMAC-SHA256 с индивидуальной солью и 600000 итераций.
В исходники, архивы продукта и резервные копии только кода база не входит.
Настройки AI/лицензия остаются в прежних файлах.

Миграция происходит один раз. После неё изменение старого пароля в settings.json
или запуск setup_ai.py не сбрасывает пароль в базе. Удаление базы не является
способом восстановления: оно теряет пользователей и возвращает старые данные
первичной миграции. Резервируйте базу SQLite штатным backup API либо при
остановленной оболочке, вместе с конфигурацией и лицензией, в закрытом хранилище.

Сессии, как и раньше, хранятся в памяти. Используйте один worker Uvicorn.
Перезапуск требует повторного входа; пользователи и роли сохраняются.
`tools/update_workspace.py` обновляет код авторизации, но не заменяет базу.
После использования многопользовательского режима не откатывайте вручную
авторизацию к старой однопользовательской версии.

## API

Все маршруты требуют admin-сессию; изменения также требуют `X-CSRF-Token`:

- `GET /api/ai/admin/users` — список без паролей/хешей.
- `POST /api/ai/admin/users` — username, password, role (`admin` или `user`).
- `PATCH /api/ai/admin/users/{id}` — role и/или active.
- `POST /api/ai/admin/users/{id}/password` — password.
- `GET /api/ai/admin/audit` — последние события.

`GET /api/ai/auth/session` возвращает username, user_id, role и csrf_token.
