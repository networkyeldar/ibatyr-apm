# Проверки релиза 0.4.0-rc1

## Автоматические проверки при подготовке

- 29 pytest tests: auth/CSRF, provider configuration, evidence, лицензии,
  смена/истечение срока, откат времени, GraphQL adapter, эксклюзивный конец периода,
  пересечения spans, недопустимые архивы и занятые порты.
- Python compileall.
- Сгенерированные shell/OAP units проходят systemd-analyze verify.
- Standalone browser QA: вход → поиск → HTTP/SQL details → JSON export;
  ширины 1500/800/390 px без горизонтального переполнения. OAP в этом сценарии —
  локальный fixture; платные LLM не вызывались.
- Реальный OAP из проверенного архива запущен с Java 17 и H2 в памяти:
  версия 10.1.0-d28dfea, readiness успешна. LIST_QUERY, DETAIL_QUERY и четыре
  metric expressions приняты GraphQL без ошибок.
- Java agent 9.3.0 загрузился в JVM Java 17; JDBC/H2 пример завершился с кодом 0.
  OAP вернул 10 сохранённых JDBC-сегментов. Это проверка передачи spans.
  GENERAL services в JDBC-only примере пуст: HTTP Entry этот сценарий не создаёт;
  полноценная HTTP → SQL трассировка приложения клиента ещё требует приёмки.
- SHA-512 обоих upstream-архивов сверены с официальными файлами Apache.

## Обязательная приёмка на целевой VM

- [ ] Чистая Ubuntu 24.04: shell first-install и системный restart.
- [ ] Persistent Elasticsearch: права, TLS, retention, сохранность после restart.
- [ ] JVM клиента: штатный startup/shutdown, поддержка его HTTP/JDBC стека.
- [ ] Проверка одной известной медленной трассировки и SQL по контрольным данным.
- [ ] Параметры времени/таймзоны и неполных трассировок.
- [ ] Внешний/локальный LLM на разрешённых диагностических данных.
- [ ] Восстановление из backup и лицензия после переноса той же установки.
- [ ] Нагрузка, CPU/RAM агента, пропускная способность и retention.
- [ ] Security review upstream-версий, зависимостей, HTTPS/ACL и коммерческих условий.

Рабочий production-сервер пользователя не изменялся. Конфигурация его текущего
агента неизвестна. Локальные проверки не заменяют приёмку на системе клиента.
