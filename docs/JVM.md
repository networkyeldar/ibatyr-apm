# JVM в iBatyr APM

Отдельная страница `/ai/#jvm`: CPU, Heap и его предел, Non-Heap, Metaspace,
состояния потоков, BLOCKED, время и количество GC (Young / Old / Normal), классы.
Выберите сервис, экземпляр и период до 24 часов. Сервис с несколькими JVM
показывается по одному выбранному экземпляру; агрегирования разных процессов нет.

- Live опрашивает последний час каждые 15/30/60 секунд; скрытая вкладка приостанавливает опрос.
- Наведение и стрелки показывают значения; кнопки рядов скрывают/показывают их.
- Клик/Enter выбирает ±2 минуты, выделение мышью — интервал внутри экрана JVM.
- «Трассировки сервиса за этот период» открывает обзор и трассировки всего сервиса;
  фильтрации трассировок по экземпляру в этом переходе нет.
- Историческая дата / 24 часа загружаются сразу, окна OAP ограничены 480 минутами.
- Выбранный исчезнувший экземпляр не подменяется другим без уведомления.
- Метрики доступны после входа в оболочку; дополнительные ключи LLM не требуются.

## Обновление существующей оболочки 0.5.0-rc1

После получения нужного коммита репозитория:

```bash
sudo python3 tools/update_jvm.py \
  --app-dir /opt/ibatyr/shell/0.5.0-rc1 \
  --port 8011
```

Скрипт проверяет WorkingDirectory systemd-службы `ibatyr-apm.service`, готовность
оболочки и OAP, компилирует Python перед заменой. Сохраняет изменяемые файлы
в `update-backup-jvm-*`, кратко останавливает только оболочку, обновляет
`ai_routes.py`, `dashboard_routes.py`, `jvm_routes.py`, `ai_web/` и запускает её.
При ошибке запуска/проверки возвращает прежние файлы. Новый frontend заменяет
локальные изменения `ai_web`; они сохраняются в резервной копии.

Настройки авторизации, LLM, лицензия, служба OAP и Elasticsearch не изменяются.
Дополнительных зависимостей нет. Скрипт предназначен для указанной структуры
установки, не для произвольной старой пользовательской сборки.

Для Mac с SSH-доступом к серверу:

```bash
ssh -N -o ExitOnForwardFailure=yes \
  -L 18011:127.0.0.1:8011 devadmin@100.72.85.197
```

Откройте `http://127.0.0.1:18011/ai/#jvm` и войдите с существующей учётной записью.

## API и единицы измерения

`GET /api/ai/jvm?service_id=...&start=...&end=...&instance_id=...`

`instance_id` необязателен: при первом открытии выбирается первый экземпляр
из отсортированного списка. Последующие запросы закрепляют выбранный ID.
Даты ISO 8601 с часовым поясом, полные минуты, конец исключён.
Ответ содержит `instances`, `instance`, `points`, `latest`, `coverage`, `warnings`.
При неизвестном ID возвращаются список экземпляров и `instance: null`.
Суточный запрос — три окна метаданных экземпляров и три запроса метрик,
общий таймаут 35 секунд. Ошибка транспорта любого окна — ошибка всего запроса;
ошибка отдельной метрики — пропуск и предупреждение.

| Поле | Единица / смысл |
|---|---|
| cpu_percent | Проценты CPU Java-процесса, уже в процентах на стороне OAP 10.1 |
| *_bytes / *_gib | Байты / GiB (1024³ байт), минутные средние |
| heap_percent | Отношение минутных средних Heap used/max; неизвестный max даёт null |
| threads_* | Минутные средние числа потоков |
| *_gc_ms | Суммарное зарегистрированное время сборок за минуту, мс |
| *_gc_count | Суммарное зарегистрированное число сборок за минуту |
| classes_loaded | Минутное среднее числа загруженных классов |

CPU ниже 1% ограничен снизу до 1% в стандартном OAP 10.1. Время GC не является
длительностью отдельной stop-the-world паузы. BLOCKED не доказывает SQL lock или
deadlock. Не все JVM/GC поддерживают все поля.

В схеме без `isEmptyValue` нельзя надёжно различить ноль и отсутствие данных.
Без положительного Heap или live threads минута скрывается как неизвестная;
это эвристика, не подтверждение полноты. В остальных минутах нули сохранены
и должны интерпретироваться с предупреждениями. Карточки показывают последнюю
минуту выбранного интервала, не подставляют более ранние значения.

## Проверки

Регрессионные тесты проверяют разбиение суток, экземпляры, единицы, пропуски,
неопределённый max памяти, ошибки OAP и deadline. Браузерная проверка использует
синтетические данные и проверяет отдельный экран, Live, период, выбор JVM,
клавиатуру, мобильную ширину и выход. Проверка реальной установки выполняется
после применения обновления оператором; тесты не заменяют её.
